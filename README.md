# 量化接单工作群 · Skills

> 把「我会这些技术」变成「有人愿意为结果付钱」。
> 三个 Skill 串成一条完整链路：诊断 → 报价 → 交付。

遵循 [AgentWork 社区](https://github.com/AlephAITech/) 的 **真场景 · 真过程 · 真结果 · 真边界** 规范。

---

## 为什么做这个

很多量化开发者技术足够，但把技术变成收入这件事没人教、也不敢教——
因为公开写出来的通常不是方法，而是「怎么白干三个月」。

这套工作群不一样：它只写**真实跑通过的路径**，包括失效的地方。

## 三个 Skill

### 1. quant-service-selling · 报价与获客

把技术能力翻译成明码标价的服务，生成三平台文案。

**包含**：
- 六项标准服务报价表（¥1,500 - ¥20,000，含工时与难度）
- 报价三条硬规矩（先收钱再开工 / 按客户省多少定价 / 企业价另算）
- 异议处理话术（贵了 / 我自己也能搞 / 能便宜点）
- 咸鱼 / 小红书 / 雪球三套文案模板
- 平台红线与自动化风险对照

**关键洞察**：
- 技术不是商品，**结果**才是
- 客户买的是「客户能看到的结果」，不是技术描述
- 企业价 ¥9,999 和个人价 ¥2,999 是两个市场

### 2. quant-data-doctor · 数据诊断

给潜在客户做**免费诊断**，让对方自己看到问题，从而自然产生付费意愿。

**七项体检**：完整性 / 静默失败 / 单位归一 / 复权 / 幸存者偏差 / 停牌涨跌停 / 前视偏差

**核心洞察**：
> 数据不对时，回测结果一定是错的，**而且看起来完全正常**。

「免费诊断 → 付费修复」是转化率最高的方式：客户不知道自己的数据有问题，
你免费告诉他，比你说「我能修」有效十倍。

### 3. onequant-deploy-kit · 部署交付

私有化部署的标准动作与交付边界。

**包含**：
- 环境自检表（Python / 内存 / 磁盘 / 网络 / SQLite 版本）
- 多源冗余与降级逻辑
- 数据管道故障排查决策树（按实测频率排序）
- 交付验收清单（含「随机抽 3 只票与券商 App 比对」）
- 7 天远程交付流程（含预付款机制）

**核心洞察**：交付的不是软件，是**「跑得起来且有人负责」**。

## 使用方式

在 WorkBuddy / 豆包中直接说：

```
帮我诊断一下这个数据有什么问题
这些技术能卖多少钱，帮我做报价单
我要给客户私有化部署一套，检查清单是什么
帮我写小红书和雪球的获客文案
```

或显式指定：

```
用 quant-service-selling 帮我写报价单
用 quant-data-doctor 诊断这个 CSV
```

## 与其他量化技能的关系

这套工作群解决**变现问题**；数据获取、回测执行、决策辅助等技能解决**技术问题**。
两者互补，不替代。

## 核心认知

1. **能被自动化的只有「怎么做」**，不能被自动化的是「该不该这么做」和「出了事谁负责」——
   客户付钱买的是后者。
2. **开源是获客渠道，不是商业模式。** Postiz：33k star → $170k MRR，零广告预算。
3. **第一个客户的价值远大于第 10 个。** 先跑通闭环，别先搭工具。
4. **企业价与个人价是两个数字。** 个人 ¥3000 会犹豫，企业 ¥9999 走审批就行。

## 真实边界

- ❌ 不承诺任何策略收益率
- ❌ 不保证公开数据源 100% 可用
- ❌ 不代客炒股、不碰客户资金
- ❌ 不用脚本/群控操作平台账号
- ✅ 保证数据管道可维护、故障可恢复
- ✅ 交付后 7 天质保
