# 数据诊断 · 建立信任的第一件工具

## 何时用

- 用户问「我的数据有没有问题」「回测结果可信吗」
- 用户说「回测很漂亮但实盘亏钱」
- 你要给潜在客户做**免费诊断**以建立信任
- 需要判断一个量化项目的结论是否可信

## 为什么这个技能是获客利器

**核心洞察：客户不知道自己数据有问题。** 你免费告诉他问题在哪，他自己会算出修复的价值——这比你说「我能修」有效 10 倍。

这是「诊断先行」策略：诊断免费，修复收费。诊断报告就是最好的报价理由。

---

## 核心原则：数据不对时，回测结果一定是错的，而且**看起来完全正常**

这是最危险的地方——错误的回测不会报错，不会异常，它会给你一个非常漂亮但完全虚假的数字。

---

## 诊断七项（按检查顺序）

### 第 1 项：完整性校验（最先做，也最常出问题）

**用户的假设「我的历史数据是完整的」通常是错的。**

```sql
SELECT date, COUNT(*) FROM daily_bars
WHERE date >= '2026-09-01'
GROUP BY date ORDER BY date;
```

正常每个交易日应有约 3800 行 A 股数据。

- 某日远低于此 → **该日数据缺失**
- 某日为 0 → 日更任务整日跳过
- 某些日期完全缺失 → 周末/节假日之外的日子就是丢了

再看同步元信息确认：

```sql
SELECT * FROM update_meta ORDER BY rowid DESC LIMIT 5;
```

**为什么这是第一项**：后面六项都要在数据完整的前提下才有意义。

### 第 2 项：静默失败检测（最隐蔽）

**问题**：某些数据接口会返回空数据但**不报错**。

表现：脚本跑完了，数据库更新了，但实际一行新数据都没进去。

检测方法：
```sql
SELECT MAX(date) FROM daily_bars;        -- 最新日期
-- 对比
SELECT date FROM update_meta ORDER BY rowid DESC LIMIT 1;
```

两者不一致 → 中间有静默失败。

**根因**：批量接口返回空列表时，很多客户端直接return 而不抛异常。

### 第 3 项：成交量单位归一（A 股特有坑）

**A 股成交量单位是「手」，1 手 = 100 股。** 但不同数据源口径不一致：
- akshare：手
- pytdx：手
- 东方财富：股
- 通达信格式：手

**混用会导致**：成交额算错、资金流向算错、成交量指标全部偏移。

检测：随机抽一只票，比对成交量与成交额的比值，看是否符合 1手=100股。

### 第 4 项：复权处理

**不做复权的价格序列，回测收益是假的。**

| 复权方式 | 用途 |
|---|---|
| 前复权 | 技术分析、连续 K 线（最常用） |
| 后复权 | 计算长期收益率 |
| 不复权 | 实际成交价对齐 |

检测：检查价格表里是否有复权因子字段，或者是否存了两套价格。

**常见错误**：用不复权数据做回测，遇到除权日价格跳空，策略会误判为暴跌。

### 第 5 项：幸存者偏差

**退市的股票不在数据库里 → 回测天然乐观。**

检测：当前股票列表数量 vs 历史上的股票列表数量。
- 如果只存「现在还在交易的票」，回测就是幸存者偏差
- 严谨做法：存全部历史股票，包括已退市的

### 第 6 项：停牌与涨跌停的处理

**问题**：停牌日没有 K 线，如果回测逻辑是「按日期取数据」，会取到前一天的数据，伪装成正常交易。

**涨跌停**：一字板买不进也卖不出。回测如果假设「在涨停价能买到」，收益会被严重高估。

### 第 7 项：横截面数据的时间对齐

**问题**：不同数据源的更新时间不同。

- 财报可能滞后 1-3 个月
- 龙虎榜T+1 才出
- 北向资金当日不一定有

**错误做法**：用当日不可得的数据做当日决策 → 这叫前视偏差（look-ahead bias），会让回测结果虚高得离谱。

检测：确认所有数据源的数据日期 ≤ 决策日期。

## 输出格式（给客户看的诊断报告）

```
【数据体检报告】

检查项                状态        说明
──────────────────────────────────
完整性          ⚠ 发现问题   2026-09-15 缺失（仅 120 行）
静默失败        ✗ 未检测     最新数据 09-14，同步记录 09-16
成交量单位      ✗ 未归一     混用「手」和「股」
复权处理        ✓ 正常前复权
幸存者偏差      ⚠ 存在     未包含已退市股票
前视偏差        ✓ 未发现

【影响评估】
· 9月15日之后的回测结果全部不可信
· 成交量指标类策略结果会系统性偏移
· 退市股缺失会高估策略实际表现

【建议修复顺序】
1. 先补9月15日缺失数据 —— 其余结论都依赖它
2. 统一成交量单位为「手」
3. 补充退市股票数据（工作量最大，可选）

【修复参考】
数据管道重建 + 历史补齐：3-5 天
仅补缺失日：1 天内
```

## 使用方式

### 场景 A：给潜在客户做诊断

1. 问他要数据库连接方式或导出一份CSV
2. 按上面七项逐项检查
3. 输出报告，**明确指出问题在哪、影响多大**
4. **不要主动报价**。让他看完报告自己算值多少钱
5. 他问了 → 报价

### 场景 B：用户自己排查

同样的流程，但每项给出可执行的修复方法。

---

## 边界与诚实原则

- **不要伪造数据让回测「看起来对」**。用户要的是真实的判断依据。
- 如果数据严重不足，直说「这个项目的数据基础不足以支撑可信回测」，不要勉强出报告。
- 诊断结论要给**置信度**：确定有问题/ 可能有风险 / 数据不足以判断，三档要分清。
